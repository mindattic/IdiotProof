1What a gapper trade is

A gapper is a stock whose premarket price has gapped up meaningfully versus yesterday's official close — usually on news, earnings, or momentum — with real volume behind the move. The trade: get in early in the premarket (the session opens at 4:00 AM ET), ride the run, and get out before the 9:30 opening bell, when gappers routinely give their gains back to the opening auction.

SCREENGap % vs. previous close, volume burst, price band — all inside your entry window.04:00–09:00 ET
BUYAll conditions pass → LLM panel → Risk Guardian → limit order (extended-hours).the moment criteria hit
HOLDTrack the high-water mark. Stops protect the whole ride.through the run
ROLLOVERArmed late in premarket: sell once price gives back N% of the run.from ~09:15 ET
FLATHard sell-by guarantees you're out before the bell, no matter what.by ~09:28 ET

IdiotProof runs this loop unattended. You dial in what counts as a gapper and how it exits; the console does the watching, the buying, and the selling.

2Quick start — two processes

IdiotProof is two programs sharing one SQL database. The database is the wire: everything you do in the browser is picked up by the trading console within ~5 seconds — no restarts, nothing to connect.

# Terminal 1 — the web UI
dotnet run --project IdiotProof.Blazor

# Terminal 2 — the trading console (the thing that actually trades)
dotnet run --project IdiotProof.Monitor

On first run, register an account in the UI. The console will log:

IdiotProof.Monitor starting — interval 5s, feed Alpaca
Monitor leader lease acquired — this instance evaluates and trades

Leave the console running

It's built for it: a supervised loop survives bad ticks with backoff, a heartbeat file lets a watchdog detect hangs, and it installs as a Windows service (sc.exe create IdiotProof.Monitor binPath="...\idiotproof-monitor.exe"). If you accidentally start two, the second waits in standby — a database lease guarantees only one instance ever trades.

3Keys: data vs. orders (and paper vs. live)

Two separate key paths, on purpose:

Market data (the console's eyes)

The console reads its data-feed keys from the machine-level MindAttic keyring. Create %APPDATA%\MindAttic\Brokers\providers.json:

{ "alpaca-paper": { "type": "alpaca", "apiKey": "PK...", "secret": "..." } }

With keys present, the console uses Alpaca REST plus a websocket stream (live trades + minute bars) automatically. Without keys it falls back to a deterministic mock feed (see dry-run mode).

Order routing (your money)

In the UI: user menu → API Keys. Enter your Alpaca key and secret, keep Paper checked, and enable “Route my orders to this Alpaca account.” Save All. From then on, your strategies place orders on your Alpaca account with your paper/live setting. Keys are encrypted at rest; the console decrypts them through a shared Data Protection key ring.

Paper first. Live is a deliberate act.

If routing is off, orders go to the built-in Sandbox broker — instant simulated fills, zero risk. That is the default and the fallback whenever anything about your keys is wrong. Going live requires unchecking Paper and confirming the red warning modal. Real money moves after that.

4Building a gapper on the Gapper tab

Option A — from a transcript (natural language)

The tab's “From a transcript” box takes any free text — a video transcript, chat notes, your own words. Click Interpret and Claude extracts the premarket gap plays it describes into candidate cards: ticker, a one-line rationale, and the dial-ins it inferred ("tight stop" → lower stop %, "let it run" → higher giveback, quoted gap sizes → the gap screen). Everything the model returns is re-validated against the same rules as the manual form; anything malformed is skipped with a warning.

You stay in the loop

Interpretation never queues anything. Each card has Queue (adds it as-is, within the 3-gapper cap) and Load into dials (copies it into the manual form so you can tweak before queueing). A transcript is untrusted input — a human clicks every queue.

Requires a Claude API key (API Keys page or the MindAttic LLM keyring).

Option B — by hand

  1. Open the Gapper tab in the top navigation.
  2. Type the ticker (e.g. NVDA).
  3. Pick a profile — Classic Gapper (5%+ gap on 2× volume), Penny Runner (10%+ gap, cheap stock, tighter exits), or Large-Cap Gap (3–12% gap at size).
  4. Click Dial in and adjust anything — every value is per-ticker. All gappers are not the same; the profile is just your starting point.
  5. Expand Preview generated IdiotScript if you want to see exactly what will run.
  6. Queue Gapper. Up to 3 can be active at once.

The queued row shows a live badge from the console. Pause, remove, or re-queue any time — changes apply on the console's next tick. One exception: while a gapper is HOLDING shares, it cannot be paused or deleted — the console must stay on the row to run the stop/giveback/sell-by exit. It flattens by the sell-by time at the latest; pause it after.

Under the hood the dial-ins become an IdiotScript strategy, the same six-phase DSL every IdiotProof strategy uses:

Ticker("NVDA")
    .Name("NVDA Gapper — Classic Gapper")
    .Session(IS.PREMARKET)
    .RequireEntryWindow("04:00", "09:00")
    .IsGapUp(5)
    .IsVolumeAbove(2)
    .IsPriceBetween(1, 50)
    .Long()
    .QuantityNotional(1000)
    .StopLossPercent(5)
    .PeakGiveback(25, "09:15")
    .SellBy("09:28")

5Profile reference — every dial

Max gap %Optional ceiling — beyond this, the move is "already gone."Useful on large caps (a 20% mega-cap gap has usually exhausted itself). Blank = no cap.

6What happens while it runs

Every ~5 seconds the console re-reads your active strategies and evaluates each one. You can watch in two places — the console log narrates every decision, and the Gapper tab mirrors it as badges:

BadgeMeaning
⏳ 2/4 · IsGapUp(5)Two of four conditions pass; it's waiting on the gap. The named verb is the first one failing right now.
⏳ 0/4 · (outside Premarket session)Market-clock gate: it only evaluates 4:00–9:30 ET on trading days. Normal at night and on weekends.
💼 HOLDING 98 @ 10.21Entry filled. The console now manages the exit instead of hunting entries.
↗ sold @ 11.48 · PeakGivebackExited, with the reason (PeakGiveback, SellByTime, StopLoss, TrailingStop, TargetHit).
⏳ (done for today)Already traded today; re-arms tomorrow automatically.

When all conditions pass, the candidate walks three gates in order before any money moves — condition match → LLM voter panel (if enabled) → Risk Guardian — then the entry goes in as a marketable limit order, flagged extended-hours during premarket (an Alpaca requirement; a plain market order would silently queue until 9:30 — exactly what you don't want).

7The sell-off brain

While holding, every tick checks four rules, first match wins:

  1. Hard sell-by — the ET time hits → flatten. Non-negotiable backstop.
  2. Hard stop — price breaches your stop % below entry → out.
  3. Trailing stop (if set) — price falls your trailing % off the high-water mark → out.
  4. Peak giveback (armed from your arm time) — the momentum-rollover exit.

The giveback rule scales with the stock's own momentum, which is what makes it fit gappers: sell when price surrenders N% of the run from your entry to its peak.

Worked example — 25% giveback

Enter at $10.00. It runs to a peak of $12.00 → the run is $2.00. 25% of the run is $0.50, so the exit floor is $11.50. At 9:15 ET the watch arms; at 9:21 the price prints $11.48 → sold, keeping ~75% of the move. A slower stock that only ran to $10.40 gets a much tighter floor ($10.30) — the exit automatically gives big runners room and small runners none.

Exits are risk-reducing, so they skip the LLM panel by design — but every one is audit-logged, and the realized P&L feeds the Risk Guardian's daily circuit breaker.

7bBacktest a day — design on the past, trade the future

The Gapper tab's “Backtest a day” section closes the loop: type a ticker, dial the profile, pick a past date, and Replay day. The replay fetches that day's bars — premarket included — plus the previous close (Alpaca when your keys are configured, the mock gap day otherwise) and runs your dials over it. Fidelity guarantee: entries use the same condition walk and exits run the same sell-off brain as the live console, so the answer to “what would have happened?” is the code that actually trades, not a lookalike.

The report shows the fills (with reasons and ET times), P&L, the run's peak and worst drawdown, a giveback grid (what every giveback dial from 10–50% would have done on that same day), and plain-English suggestions — “the peak came after your exit; this day rewarded more patience”, “your stop was never close — tighten to ~4%”. If it never entered, it names the exact condition that blocked it.

Apply tuned dials loads the hindsight profile (best giveback, a stop informed by the day's real drawdown — never loosened, gap screen just under the day's actual gap) into the manual form, ready to queue for a real trading day. Nothing tunes itself; you apply it.

8The safety model

LayerGuarantee
Sandbox defaultNo real order unless you explicitly opted your account in. Anything wrong with keys → falls back to simulation, never to someone else's account.
Three gatesConditions → LLM voter panel → Risk Guardian, in order. Any gate blocks the fire and records why.
Risk GuardianFinal veto on every entry: a stop must exist and be on the correct side, worst-case loss ≤ your per-trade cap, stop distance sane, account-risk % capped, and a daily-loss circuit breaker that halts trading for the day.
One trade per dayA gapper that traded today stands down until tomorrow (unless the strategy opts into Repeat()).
Hard sell-byPositions cannot be carried into the open — the flatten rule outranks everything.
Single traderA database leader lease means two consoles can never double-fire the same strategies.
Paper vs. liveLive requires unchecking Paper and confirming the red modal. Everything defaults to paper.

9Dry-run mode (no keys, no money)

Rehearse the entire lifecycle with zero external dependencies:

# Windows (PowerShell)
$env:IDIOTPROOF_FEED = "mock"
dotnet run --project IdiotProof.Monitor
  1. Queue a ticker that starts with GAP — e.g. GAPT. The mock feed fabricates a textbook gap day for any GAP* symbol: previous close → gapped 4AM open → momentum run → rollover before the bell, with bursty premarket volume so the volume screen can actually pass.
  2. Leave order routing off — fills go to the Sandbox broker's simulated book.
  3. Watch it buy, hold, and sell in the console log and on the tab.

The clock is still real

The session gate runs on the actual US-Eastern wall clock even in mock mode. Entries only fire 4:00–9:00 AM ET, Monday–Friday. At any other time you'll (correctly) see (outside Premarket session).

11Troubleshooting

SymptomCause / fix
(outside Premarket session)Not a bug — it's outside 4:00–9:30 ET on a trading day. The gapper wakes up at 4:00 AM ET.
no previous close available — gap conditions will fail closedThe feed couldn't supply yesterday's close (bad symbol, no daily data, feed error). By design the gap check then blocks rather than passes. Check the ticker and your data keys.
Entry order rejected: extended-hours must be Limit + DAYOnly possible with hand-authored strategies — the gapper factory always emits compliant orders. Fix the strategy's order type.
✗ VETOED by LLM panelLLM voting is enabled and the panel rejected the setup. The audit log records the panel's reasoning. Disable voting or trust the veto.
✗ BLOCKED by RiskGuardian — Would exceed daily loss limit…The circuit breaker or a risk cap tripped. That's the system working; caps live in your user risk preferences.
(done for today)This gapper already traded today. It re-arms at the next ET trading day.
Another Monitor "stands by" instead of tradingA second console instance is running; only the leader trades. Stop one, or let the standby take over when the leader dies.
Per-user routing ignored (orders hit Sandbox)Check all three: keys saved on the API Keys page, the "Route my orders" toggle is ON, and both processes share the same Data Protection key ring (automatic in dev; DataProtection:KeyRingPath in production).
